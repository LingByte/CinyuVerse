# 使用指南

本文档介绍 CinyuVerse 的日常写作流程与 v0.3 功能。安装与环境见 [quick-start.md](./quick-start.md)。

## 运行项目

### 桌面开发（推荐）

在仓库根目录执行：

```bash
npm install          # 首次
npm run dev:tauri
```

- 前端开发服务器：`http://localhost:9090/`
- Tauri 会自动编译 Rust 并打开桌面窗口
- 首次编译约 1～3 分钟

### 仅 Web 预览

```bash
npm run dev
```

无法打开本地文件夹、无法调用 Rust AI，仅适合查看 UI。

### Go Story 后端（可选）

ActivityBar「后端」面板依赖 Go HTTP 服务，与本地 Rust 流水线**独立**。需要时：

```bash
cd backend
go run ./cmd/server
```

默认地址 `http://localhost:4567`。可在 `backend` 目录配置 `.env`（见 `STORY_PROJECT_ROOT`、`STORY_HTTP_ADDR`）。

### 配置 AI

```bash
cp src-tauri/.env.example src-tauri/.env
```

编辑后**重启** `npm run dev:tauri`。详见 [ai-configuration-guide.md](./ai-configuration-guide.md)。

## AI 助手（Ctrl+L）

打开右侧抽屉后，顶部有两个入口：

| 标签 | 能力 |
|------|------|
| **本地对话·创作** | Rust 后端：多轮对话（持久化）+ 三层创作流水线 |
| **后端对话·创作** | Go Story：智能体对话 + 写下一章/审核/润色等流水线 |

### 本地：对话 vs 创作

在「本地对话·创作」内再切换：

| 模式 | 用途 |
|------|------|
| **对话** | 多轮问答、续写、规划；会话按工作区保存在 localStorage |
| **创作** | 大纲→正文→校对三层流水线，结果可写回当前章节 |

点击 **+** 可新建本地对话会话。

### 后端：对话 vs 创作

在「后端对话·创作」内切换（需 Go 服务已连接并选择书籍）：

| 模式 | 用途 |
|------|------|
| **对话** | 自然语言驱动智能体：规划、续写、读设定 |
| **创作** | 单步工具：写下一章、规划、起草、审核、修订、润色 |

启动 Go 后端：`cd backend && go run ./cmd/server`

## 第一次写作

1. 欢迎页点击进入 IDE
2. **文件 → 打开文件夹**，选择小说项目目录（内含 `.md` 章节或空目录）
3. 左侧 **目录** 面板浏览、新建、删除文件
4. 点击章节在中间编辑器打开
5. `Ctrl+L` 打开右侧 **AI 助手抽屉**
6. `Ctrl+S` 保存当前文件

项目元数据（角色、大纲、设定等）保存在工作区下的 `.cinyuverse/` 目录。

## AI 助手（本地 Rust）

IDE 主抽屉使用 **WorkspaceAiPanel**，通过 Rust 后端调用 LLM（非 Go）。

### 简易单模型

- 适合：续写、问答、单轮改写
- 自动注入工作区设定、大纲、当前章节上下文

### 三层流水线

依次执行：**大纲要点 → 正文撰写 → 校对润色**。

1. 在抽屉顶栏切换到「三层流水线」
2. 输入写作指导（可选）
3. 发送后查看各阶段输出，最终结果可写入当前章节文件

**锁定上下文**：在「锁定上下文片段」区粘贴关键设定并「固定」，截断章节正文时会优先保留这些片段。

**提取文风样本**：顶栏 Sparkles 按钮，从现有章节采样写入 `project.json`。

独立子窗口（detach AI）仍使用 `AiChatPanel`，与主抽屉能力略有不同。

详见 [ai-panel-usage.md](./ai-panel-usage.md)。

## AI 异步任务（批量润色 / 生成）

ActivityBar → **任务** 面板：

| 任务类型 | 说明 |
|----------|------|
| 提取文风样本 | 一次性提取文风 |
| 剧情审校 | 规则检测（不含 LLM 深度，深度审校用菜单项） |
| 批量润色队列 | 按大纲绑定的章节逐章润色 |
| 批量生成队列 | 按细纲逐章生成正文 |

**批量流程**：

1. 在大纲面板为章节绑定 `file_path`
2. 任务面板点击「+ 批量润色队列」或「+ 批量生成队列」
3. 点击任务卡片 **「启动 AI 逐章」**
4. 系统自动：入队 → 构建章节队列 → 逐章调用 LLM → 写回文件 → 更新进度

需已配置 AI API。处理中可在任务卡片查看进度条。

## 剧情审校

**文件 → 剧情审校报告**：

1. 先运行规则检测（大纲绑定、时间线、细纲空缺等）
2. 默认附加 **LLM 深度分析**（人物弧光、伏笔、节奏等）
3. 报告弹窗可切换「问题列表」与「完整报告」
4. 最新报告同时写入 `.cinyuverse/plot_audit_latest.md`

菜单审校为深度模式；任务面板中的「剧情审校」任务仅规则检测。

## 备份

ActivityBar → **备份** 面板，或 **文件 → 增量备份工作区**：

| 方式 | 说明 |
|------|------|
| 增量备份 | 对比 `manifest.json`，仅 ZIP 有变更的文件；无变更时提示「无变更文件」 |
| 全量打包 | 整个工作区 ZIP（排除 `node_modules` 等） |

备份文件位于 `.cinyuverse/backups/`。

## Go Story 后端 + 本地流水线桥接

1. 启动 `go run ./cmd/server`（`backend` 目录）
2. ActivityBar → **后端**：连接后管理书籍、写下一章
3. 在编辑器打开某一章（虚拟路径 `cinyuverse://story/...`）
4. 同时 **打开本地工作区文件夹**（用于 Rust API 与元数据）
5. 后端面板底部 **「三层流水线处理当前章」**：
   - 用本地 Rust 三层流水线处理当前章
   - 结果写回 Go 章节存储

Go 后端流水线与本地 Rust 流水线**相互独立**；桥接按钮显式使用本地配置。

## 大纲与章节

- **大纲** 面板：维护卷/章结构、细纲、时间线
- 章节需 **绑定正文文件路径**（`file_path`），批量任务与字数统计才生效
- 大纲操作：从细纲生成章节、基于新大纲改写正文（菜单或大纲面板按钮）
